# Coastal Systems Research

Research workspace for a small group working on coastal erosion modelling.
Papers, funded work, consortium responsibilities and collaborator notes.
Teaching is in a separate workspace.

**Owner:** J. Halvorsen (fictional)
**Storage:** cloud-synced. No version control, so no undo on bulk operations.
**Started:** 2025-11-03

*This is an example workspace. Every person, project, grant and journal in it
is invented.*

## Why this shape

Organised by kind of work rather than by year, because a paper and a
consortium responsibility have completely different lifecycles. Manuscripts
under review and partner data are confidential and never leave this tree.
Manuscripts live in Overleaf and model code in git; this folder holds the
private layer only.

## Structure

- `projects/` — work with an end: papers, reports, deliverables.
- `areas/` — standing responsibilities with no end date.
- `people/` — one note per collaborator, safe to share.
- `resources/` — templates and reusable material.
- `inbox/` — unclassified incoming material.
- `archive/` — finished or dead work.

## How to work here

- Open sessions inside this workspace, not in its parent folder, so the local
  instructions and skills load.
- Each unit's `README.md` says what it is; its `STATUS.md` says where it is.
- The board of pending work is generated from `STATUS.md` files. There is no
  hand-maintained task list.

## Related

- Manuscripts: Overleaf, linked from each project `README.md`.
- Model code: Git repositories, linked from each project `README.md`.
- Fieldwork data: institutional store, not here.
- Teaching workspace: separate tree, no material crosses between them.
